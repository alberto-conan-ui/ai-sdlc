# Modes

A mode names where the session is working and how much to trust the Memory it finds. Every session is in one of four, always.

## Reflecting

The Human Lead and the stance work on Memory together to build the understanding the rest of the work will consume.

### When to use

When the understanding the work needs is not yet in Memory, or the existing focus is too vague to be acted on. Skipped when a usable focus already exists or the work is small enough to act on without one.

### Goals

- Create a lean, abstract focus with clear gates
- Create lean, useful Knowledge Tree nodes Executing will use to fulfill the focus and its gates

## Planning

The session is breaking the approach down into the phases Executing will follow.

### When to use

When the approach is understood and the focus is stable, but delivery is not yet decomposed into phases. Skipped when the work is small enough to hold the plan implicitly.

### Goals

- Decompose the focus into phases Executing can act on in order
- Produce phase-level gates so progress can be verified independently of the full focus gate

## Executing

The session is producing the Payload against the focus and phase gates. Memory is the authoritative input; the plan is followed.

### When to use

When a plan is in place, its phases are ordered and gated, and the Human Lead has approved it. The session's job is to move the Payload, not re-negotiate what to do.

### Goals

- Deliver Payload changes that meet the focus and phase gates
- Record progress in Memory — journal, action tree, knowledge tree — so future sessions can continue

## Salvaging

The session is rewriting Memory the Human Lead no longer trusts. Substantial redirection has been called, and the Memory that accumulated around the prior approach cannot be carried forward.

### When to use

When the Memory accumulated around the current approach can no longer be trusted to carry the work forward, and the Human Lead has called for rewrite.

### Goals

- Rewrite the Memory that can no longer be carried forward
- Restore Memory to a state the session can re-enter one of the other three modes from

## Transitions

A transition happens when the symptoms of the current mode say it has run out. The session names the transition explicitly — which mode is being left, which is being entered — rather than drifting across it.

**Toward Reflecting.** The session finds itself re-opening design questions under the cover of planning or implementation. Gates no longer match what has been learned. A plan cannot be fixed because the understanding it assumed was never actually built.

**Toward Planning.** The focus is stable and the approach is clear, but the session is about to start changing Payload files without a decomposition. Phases are visible but not yet written down.

**Toward Executing.** The plan's phases are ordered, the phase gates are set, and the Human Lead has confirmed the plan is good enough to act on. The session is ready to cross from Memory-work into Payload-work.

**Toward Salvaging.** Corrections are stacking — each one revealing the last was built on something that should not have been trusted. Prior artifacts feel like liabilities rather than resources. Extension is not recovering the work; only rewrite is. The Human Lead calls the transition; the session flags the symptoms but does not self-transition.

**Away from Salvaging.** Memory has been rewritten into a state the session can re-enter one of the other three modes from. The Human Lead calls this — the session cannot self-verify that trust has been rebuilt.
