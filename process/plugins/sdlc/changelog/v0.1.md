# SDLC v0.1 — Initial Release

**Date:** 2026-04-06
**Requires core:** v0.3+

**Summary:** First version of the SDLC plugin. Designed for software development projects. Extracts the stances, conventions, and workflow that were previously baked into core (pre-v0.3).

**Status:** Released.

---

## What this plugin provides

### Stances

- **Architect** — designs systems, evaluates trade-offs, writes specs. Combines Strategist and Builder archetypes. Entry point: `roles/architect.md`.
- **Tech Lead** — implements the plan. Primarily Builder archetype. Writes code, runs tests, stays within the approved spec. Entry point: `roles/tech-lead.md`.

The **Auditor** is a core stance available to all plugins (see `roles/auditor.md` in core).

### AT node types

Domain-specific node types layered on core's container/leaf primitives:

- **goal** — top-level container. Always gated.
- **topic** — grouping container for related work.
- **phase** — stage within a goal (e.g., design, implementation, validation). Gated.
- **step** — granular work unit within a phase.
- **task** — leaf node. Atomic work item.

### Workflow extension

Design → implementation cycle with formal phase specs. The Architect produces a spec; the Human Lead reviews it; the Tech Lead implements against it. Spec review is a plugin checkpoint layered on the core focus gate.

### Conventions

- Phase spec format and naming
- SDLC-specific recording by stance
- Node naming: `NN.type.kebab-case-name/`

### Joins

| Plugin file | Core file | Relationship |
|---|---|---|
| `roles.md` | `process/roles.md` | Substitution — two concrete stances replace core archetypes |
| `workflow.md` | `process/workflow.md` | Addendum — design→implementation cycle layers on core focus/modes |
| `action-tree.md` | `process/action-tree.md` | Addendum — SDLC node types layer on core containers/leaves |
| `conventions.md` | `process/conventions.md` | Addendum — SDLC naming and file types layer on core grammar |

## Migration Steps

**New plugin — no migration path.** Projects adopting SDLC for the first time:

1. Declare `plugin: sdlc` and `plugin_version: "0.1"` in `workspace.yaml`.
2. Set `plugin_readme` to point to `process/plugins/sdlc/ai_readme.md`.

**Projects migrating from pre-v0.3 (where SDLC was baked into core):**

The v0.22 → v0.3 core migration handles the structural changes. For the plugin specifically:

1. Your existing AT node types (goal, phase, step, task) are now SDLC plugin vocabulary — they continue to work, no renaming needed.
2. Your existing stances (Architect, Tech Lead) are now SDLC plugin stances — same names, same behavior.
3. Add the plugin declaration to workspace.yaml as above.
